# Internationalization (I18N)

GitHub does not pick a README from the browser language. This template keeps **English as the canonical source** and ships **full companion docs** in Simplified Chinese, Japanese, and Korean (VRChat / East-Asia audience).

<!-- I18N:START -->
**English** · [简体中文](i18n/zh-CN/I18N.md) · [日本語](i18n/ja/I18N.md) · [한국어](i18n/ko/I18N.md)
<!-- I18N:END -->

## Layout

| Kind | English (canonical) | Localized sibling |
|---|---|---|
| Landing | `README.md` | `README.zh-CN.md`, `README.ja.md`, `README.ko.md` |
| Agent contract | `AGENTS.md` | `AGENTS.zh-CN.md`, `AGENTS.ja.md`, `AGENTS.ko.md` |
| Legal | `DISCLAIMER.md` | `DISCLAIMER.zh-CN.md`, `DISCLAIMER.ja.md`, `DISCLAIMER.ko.md` |
| Init questions | `templates/INIT_QUESTIONNAIRE.md` | `templates/i18n/<locale>/INIT_QUESTIONNAIRE.md` |
| Other docs | `docs/*.md` | `docs/i18n/<locale>/` when a translation exists |
| Owner overlay | `OWNER.example.md` | gitignored `OWNER.md` (owner's language; not a required translation) |
| Eval rubric | `docs/EVAL.md` | English only (like tests). Not translated. |

`locales.json` is the machine list of supported BCP-47 tags. Filenames use `zh-CN` (widely used on GitHub) rather than `zh-Hans`.

Code fences, commands, package names, and GitHub URLs stay untranslated.

## What agents must do on init

1. Resolve locale, in this order: **how the user is already speaking** → `local.json` `ui_language` → env `WORKSTATION_UI_LANG` / `VRC_DCC_UI_LANG` → Windows UI culture → `en`.
2. Read the matching `AGENTS.<locale>.md` (fallback `AGENTS.md`) and the matching questionnaire. If `OWNER.md` exists, read it. Pipeline steps: `docs/i18n/<locale>/WORKFLOW.md`.
3. **Chat in that locale.** Ask Q0 if still ambiguous.
4. Persist `install_root` in gitignored `local.json` on `bootstrap.ps1 -Apply`. Persist `ui_language` only after the handshake, or when `-UiLanguage` / `WORKSTATION_UI_LANG` / `VRC_DCC_UI_LANG` is set — an OS English UI must not lock out a Chinese/Japanese/Korean chat. A non-empty `ui_language` is never overwritten.
5. Keep **git commits in English**. Do not commit `local.json`.

`scripts/resolve-locale.ps1` implements the same order for bootstrap.

## Humans

Use the language bar at the top of each README. Deep pages under `docs/i18n/` have the same bar pointing at siblings.

Pipeline pages (`WORKFLOW`, `UNITY`, `ATTACH`, `RULES`, `AI_USAGE_GUIDE`) ship under `docs/i18n/<locale>/`. Skill bodies stay English so tool names stay auto-discoverable; the conversation still follows the resolved locale.

## Adding a language

1. Add the tag to `locales.json`.
2. Translate README / AGENTS / DISCLAIMER / questionnaire.
3. Translate `docs/I18N.md` into `docs/i18n/<locale>/I18N.md`.
4. Keep section order identical to English. Update the `<!-- I18N:START -->` selector in every variant.
