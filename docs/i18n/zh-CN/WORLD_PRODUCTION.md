# 使用现有工具制作 World

英文规范：[WORLD_PRODUCTION.md](../../WORLD_PRODUCTION.md)。

在主人点名的 World 工程里，现有 Unity / Blender 工具可以直接用于制作。
S01-b / S01-c 是工位定制适配器的研发计划，不是建模、导入、场景编辑、
Udon 开发、编译或测试的前置条件。

1. 从工程交接恢复真实路径、当前操作者、已接受场景、保存状态和剩余验收。
   先核对当前磁盘 / Editor 状态；无 Git 工程用相关文件哈希与备份。
   沿用已经获得的任务授权，正常推进范围内的可恢复制作和检查。
2. 优先使用已连接的原生 MCP。必要时使用已安装的同一提供者 CLI 或 MCP SDK，
   查询实际工具 schema，选择发现到的实例 ID，再读回工程路径与场景。
   连接端口不能代替目标身份；重连或 domain reload 后重新确认。
3. 使用实际可用的场景、组件、资源、脚本和 Editor 工具。
   工程自己的 Editor C# / Blender 构建脚本可以用于可复现制作。
   对已暴露且已授权的通用执行工具，根据具体操作与目标判断用途。
   `maps/allowlist.py` 只管工位命名工具客户端，不会禁用原生 MCP、CLI、SDK
   或工程构建脚本。未实现的工位 `world_*` 不能冒充可用工具。
4. 每片做出完整可检查的成果，例如一个布置完成的房间或可玩的交互。
   复用合适资产和已验收成果。必要时在工程自己的审查场景验证模型、材质、
   比例和碰撞，保存后重新打开确认，再整合到主场景。
5. 同一 Editor / 重叠资产保持一个操作者。World 不继承 Avatar 握手、Booth SKU
   配额或固定工具次数 / 会话上限。同一任务可以连续推进多片；超时先检查
   是否已经执行，再决定重试。上下文压缩后不重复已完成的生成或导入。
6. 区分文件完整性、视觉、C# / Udon 编译、ClientSim、Desktop、PCVR 和真实多人证据。
   按改动需要测试；未测试的层级如实记录。授权制作可以包含 Play、保存、导入和
   Build & Test；SDK Build & Publish 由主人操作。
7. 工程已有任务卡和回执格式可继续用。工位网页交接模板及检查器按需采用，
   不因格式不同重做有效成果。交接保留实际输出、验证结果和下一步。

可选 World maps：同一 holder 可连续 `begin` 不同 REVIEW 行；`mutated` 递增变更版本。
`reset` 释放租约与当前片段，但保留变更记录，不能把旧证据变成新证据。
旧 Overlay 的 Avatar SKU 字段不再限制 World，下一次保存 JOB 时移除。
