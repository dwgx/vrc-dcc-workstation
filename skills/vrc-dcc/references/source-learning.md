# Learn from resource libraries and tool repositories

Use when an authorized World/avatar question needs a resource catalog, external
repository or documentation collection. Start with the decision the research
will change, then inspect the relevant content. The optional
[research executor brief](../../../templates/RESEARCH_EXECUTOR.md) supports a
separate collector returning evidence to the station coordinator.

## Identify what is available

Record the source URL, inspected revision or snapshot date, and what it contains.
Authored tutorial bodies, code, video metadata, transcripts and archive URLs
provide different evidence. A title, link check, credibility badge or downloaded
repository does not establish that the procedure was read or works today.

Use static, data-only inspection for an initial code/catalog inventory; do not
import or execute vendor code merely to count its declared capabilities. Runtime
checks belong to the authorized project task and retain their own evidence. Count
actual registrations and unique names rather than repeating README totals.
Trace a useful tool through its handler and return value. Classify implemented
code, heuristic checks, generated templates and untested runtime behavior.
For large libraries, keep a searchable topic/source index and retrieve relevant
entries on demand instead of loading every record into every agent's context.

## Read and reconcile

Track the original author so mirrors, quotations and an AI summary of a page do
not become independent corroboration. Record the content actually inspected, a
precise locator, applicable versions and the claim it supports. Keep publication,
archive and access dates distinct. An inaccessible page stays an uninspected
lead; use normal alternative access or a related original source as useful.

For technical changes, check current primary documentation and code. Explain
conflicts with old tutorials and retain useful historical methods with their
conditions. A completed web analysis is a candidate synthesis until its material
claims are checked. Local code inspection is not Blender, Unity or client evidence.

## Make learning usable

For each useful mechanism, return its purpose, inputs/outputs, prerequisites,
source evidence, a concrete example and a proposed station improvement with an
appropriate validation step. A resource catalog can guide discovery; a code
repository can supply implementation patterns; a tested project can supply
runtime evidence. Keep their roles visible.

Absorb the smallest useful method into an existing playbook, optional template
or tool. Preserve the owner's functioning tool routes. A fixed-port client,
incomplete validator or stale preset calls for a scoped improvement and version
checks, not removal of all measurement, UV, material or export capabilities.
World and Avatar can share geometry/material techniques while retaining their
different scene, networking and SDK requirements.

Save raw research privately. Check attribution and reuse terms before publishing
source code or text; a collection's links do not grant rights to linked assets.
Publish rewritten methods with direct source references. Track proposals,
implementation and runtime acceptance separately in the coordinator's record.
Return through the owner's designated task channel when authorized. Continue
from the saved source cursor when a new direction arrives; research does not
require a recurring automation.
