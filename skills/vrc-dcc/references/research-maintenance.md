# Continue useful research across agents

Use for authorized World/avatar research and station improvement. This is a
station task: start from `notes/HANDOFF.md`, not an avatar handshake or live
Editor connection. Research can continue while a project's production writer
works independently.

## Recover the delta

Keep a small private source board, optionally copied from
[RESEARCH.md](../../../templates/RESEARCH.md) to ignored `notes/RESEARCH.md`.
Record the authoritative project path, source tasks/roles, last consumed turn
or revision, evidence file fingerprints, accepted decisions and current gaps.
Titles, agent models and checkout paths can change; recover actual identity and
current project records instead of treating old labels as facts.

Read the handoff and one relevant source result. Compare compact task status
or file fingerprints before fetching more history. Use installed chat-history
tools for a missing local-session decision, or web archive tools for an exported
web conversation. Keep Owner instructions, assistant proposals, tool evidence
and superseded verdicts distinguishable. Do not replay completed requests.

## Research only a consequential gap

State the decision a result will change, the installed versions, evidence
already available, unresolved question and desired return. Use
[web-handoff.md](web-handoff.md) for delegated browser work; use
[MATERIAL_TASK.md](../../../templates/MATERIAL_TASK.md) for material production
or [CHAT_RESEARCH.md](../../../templates/CHAT_RESEARCH.md) for station adapter
architecture. Send only task-relevant context authorized for that destination.

Record the requested model and actual visible selection independently. Reopen
the saved conversation to recover an uncertain send; a timeout is not permission
to submit the same request twice. A research reply needs primary-source checks
for consequential technical claims and local tests for claimed local behavior.
Save unsupported proposals as proposals, not capabilities.

## Turn evidence into a portable improvement

1. Extract the general mechanism and the conditions under which it works.
2. Preserve useful project tooling routes. A local occupied Editor, paused job,
   addon limitation or permission boundary is a source-specific fact; it does
   not disable the technique for every clone.
3. Patch the existing skill, optional task template or small tool that helps
   another producer act. Use references for detail rather than enlarging every
   skill's startup prompt. Keep private geometry, task IDs and assets in overlay.
4. Validate the behavior and independently review the claim. Distinguish offline
   tests, source inspection and actual DCC/engine evidence.
5. Publish under the owner's existing authorization and remote convention.
   Record landed commit, validation and unconsumed source revisions in the
   handoff. A research answer alone is not a landed station update.

When recurring follow-up is requested, use the runtime's supported scheduler and
save its existing task/automation ID in the private board. Check for duplicates
before creating another. Continue from source cursors; remain quiet when nothing
actionable changed unless the owner requested periodic reports. Cadence does not
require a new web request, repository change or commit on every wake.
